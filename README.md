# mrhakan.github.io

A Windows 98 desktop that happens to be a personal site. Plain HTML, CSS
and JavaScript, served straight off GitHub Pages. **There is no build
step** — what is in the repo is what the browser gets, and that is the
whole point.

## Running it

```sh
npm run serve      # python3 -m http.server 8099
npm test           # the whole headless suite
npm run css        # rewrite css/tailwind.css after using a new utility class
```

Winamp's **enter concert mode** button opens the music room. All 23 tracks
have distinct sets and choreography: a rainy cathedral, bunny dancers,
a robot factory, a walking line character, Persona's cut-paper poster,
Portal's test chamber, Metin2's pagoda, a vintage television and a lane war at dusk, among others.
Bass drives the set's lights and props through the existing audio analyser.
Local Motion timelines reveal the titles with staggered spring transitions.
Pause holds the stage, and **Esc** or **back to desktop** restores the
desktop. The player remains available in concert mode on phones too.
The compact player has an expandable **setlist**; choosing a song closes it
to keep the artwork visible.
Reduced motion keeps a still scene, and hidden tabs stop drawing. Slower
devices show the scene in concert mode at 20 fps with a smaller backing canvas;
the background renderer rests while the desktop is open.

The browser tests need Playwright's chromium and a server on :8099:

```sh
python3 -m http.server 8099 &
node .github/scripts/browser-check.mjs
node .github/scripts/browser-echoes.mjs
node .github/scripts/browser-mobile.mjs
```

## Things that will bite you

- **A phone zooms the whole page out if anything sticks out sideways.**
  One element past the right edge and the browser widens the layout
  viewport to cover it, so every window renders at half size in the
  middle of the screen. The news ticker does exactly that for half of
  every loop and is only clipped by a class in a second stylesheet, so
  `#marquee-rail` and `html { overflow-x: clip }` are the floor under
  it. `browser-mobile.mjs` samples the page width right through the
  marquee loop.
- **A finger drag emits pointer events and nothing else.** No browser
  synthesises `mousemove` for one — only a click at the end of a tap —
  so a titlebar wired to `mousedown`/`mousemove` is immovable on a
  phone. Window dragging is on pointer events with capture.
- **`createMediaElementSource` is a one-way door.** It takes the
  `<audio>` element off the speakers and hands its output to the web
  audio graph. Call it while the AudioContext is suspended — which is
  how a phone creates one — and the track plays with the clock ticking,
  the progress bar filling and no sound at all. The graph is only ever
  built once the context is genuinely running.

- **Multiplayer tested from one machine proves nothing about the network.**
  Two browsers on the same computer never need TURN or a relay, so a dead
  server looks exactly like a working one. That hid the free TURN servers
  vanishing and a relay list that was down to one working relay. The relays
  are other people's servers and they change: `npm run relays` checks them at
  game rate, for long enough to get past the limits a quick check never sees,
  and `npm run relays -- --lobbies` checks that they pass on the open lobby
  list's listings, questions and goodbyes.

- **The open lobby list is strangers' writing.** Anyone can post to a public
  relay, so `games/lobbies.js` checks every listing against the game
  catalogue, cuts it to length, checks its signature and escapes it before it
  is drawn. A flood of new keys can fill the list for as long as it keeps
  posting; it cannot break it. A tab that is killed outright cannot say
  goodbye, so its listing lasts until the 40 second time limit.

- **`sw.js` stays at the root.** A service worker's scope is its own
  directory; moving it into `js/` would silently stop it controlling the
  site.
- **Every `url()` in `css/style.css` is absolute.** They resolve against
  the stylesheet, not the page, so a relative one broke the icon font the
  moment the file moved into `css/`. `check-motion.mjs` fails the build
  on a relative one now.
- **The service worker precaches by URL.** Move a file and its entry in
  `PRECACHE` or `PRECACHE_LATER` has to move too — `check-games.mjs` fails
  if a precached URL does not exist. `PRECACHE` is what it takes to boot the
  desktop, and the install waits for it. `PRECACHE_LATER` is everything that
  loads on demand: `js/lazy.js` asks for it once somebody has stayed fifteen
  seconds, unless their connection asked to save data.
- **`css/tailwind.css` is generated**, by `npm run css`, from the classes in
  the three pages, `js/` and the games the desktop can open. Reach for a
  utility nothing has used yet and re-run it, or `check-startup.mjs` fails.
  A class built up at runtime from pieces (`'text-' + colour`) cannot be seen
  by either of them, so spell it out. The file comes after `style.css` on
  purpose: it was injected last when it came off a cdn, and plenty of
  `style.css` has been losing to it at equal specificity ever since.
- **A function in `js/lazy.js` answers late.** Its window appears after the
  caller has moved on, so only functions that are called and not read can go
  in the table. A `DOMContentLoaded` listener in one of those files never
  fires, since the page finished loading before the file arrived. A new
  function that another file calls goes in the table, and `check-startup.mjs`
  fails if the table names something the file does not declare.
- **The hidden sections build themselves when opened.** The repo grid and the
  playground catalog do not exist until `showSection` first asks for them.
  Nothing else can assume they are there.
- **`check-startup.mjs` has a budget.** Over it means finding out what grew.
  A new window belongs in `js/lazy.js`, not in a bigger number.
- **`data/github.json` is generated**, once a day by
  `.github/workflows/github-data.yml`. Do not hand-edit it.
- **`window.innerWidth` is not the viewport on a phone.** If anything
  overflows horizontally the browser widens the layout viewport to fit it
  and `innerWidth` widens too — measured at 1648 on a 412px screen. Use
  `TOUCH.viewportWidth()`, which reads `documentElement.clientWidth` and
  agrees with the media queries.
- **Route names live in three files that cannot import from each other.**
  `js/web.js` resolves them, `404.html` redirects to them (it is a separate
  page, so it carries its own copy), and `sitemap.xml` lists them. The keys
  in `appActions()` are the source of truth, and a few have a nicer public
  name — `usespage` is `?app=uses`. `check-web.mjs` holds all three lists to
  the real routes; it is what caught `/uses` pointing at nothing.
- **`feed.json` is generated** from `feed.xml` by
  `npm run feed`. Add an `<item>` and re-run it, or `check-web.mjs` fails.
- **`js/web.js` loads last, on purpose.** It wraps `createAppWindow`,
  `closeAppWindow`, `startMenuAction` and `showSection`, which have to exist
  before it runs. Move its `<script>` tag up and the deep links stop working
  silently.
- **`.doc-` belongs to the slash pages; my documents is `.docs-`.** Both
  features grew a "document window" and both reached for the same prefix.
  `js/documents.js` loads second, so it won, and every `/now`, `/uses` and
  colophon window rendered in MS Sans Serif rather than the Courier its own
  rule asks for — silently, for weeks. `check-web.mjs` fails the build if
  the two namespaces overlap again.
- **The document font size is `var(--doc-font-size)`.** The A-/A+ buttons
  set it on the root element. A second rule hard-coding `font-size` on
  `.doc-body` would win and kill the buttons without an error, so
  `check-web.mjs` looks for one.
- **`.doc-body`'s font size, and everything else `instant()` touches.**
  With motion off, `FX.animate` applies the keyframe's end state directly.
  It used to apply three properties and drop the rest, so a keyframe that
  moved something by `left` never happened for anyone with reduced motion
  on — and nothing said so. `check-motion.mjs` holds it to the whole
  keyframe now.
- **Fullscreen is two implementations.** The Fullscreen API where it
  exists; a `.fs-faux` class pinning the window over the viewport where it
  does not, which is Safari on iPhone and any iframe without
  `allow="fullscreen"`. Everything downstream — `.fs-active`, the canvas
  fitting, Escape — is driven off the same class either way, so a change
  to one needs checking against the other.
- **Touch rules key off `pointer: coarse`, never a width.** A narrow
  desktop window is not a phone and a tablet with a stylus is not a
  fingertip. The bigger tap targets and the 16px inputs must not appear
  under a mouse — that is what keeps this looking like 1998.
- **A new window has four places to be registered**, and
  `check-web.mjs` fails if any of them is missed: `appActions()` in
  `js/index.js`, the start menu in `index.html`, the search index in
  `js/extras.js`, and `PRECACHE_LATER` in `sw.js`. It also checks that every
  `unlockAchievement()` names an achievement that exists, and that every
  class the new files invent has a style.
- **An achievement is one line and one call.** A line in `ACHIEVEMENTS`
  in `js/fun.js`, and `unlockAchievement('id')` where it happens. The
  trophy room shelves it by its prefix (`dungeonz_`, `aot-`, `echoes-`,
  `troll_`...), so a new one for an existing game needs nothing else. An
  id that does not exist does nothing at all, silently: that is how wizardz
  handed out two achievements for weeks that nobody could ever get.
  `check-trophies.mjs` fails the build on one now. A `hint` on the line is
  what a locked one shows instead of its description.
- **The playground's pages do not load the desktop's scripts.** So they
  cannot call `unlockAchievement`. Their achievements are counted from the
  records they leave in localStorage, which the trophy room finds by the
  game's folder name (`lights-out-98-best` is `games/lights-out/`). A game
  that saves under some other name goes in `ALIAS` in `js/trophies.js`.
- **The install button only exists when there is something to install.**
  Chrome and Edge fire `beforeinstallprompt` once, early, when the site
  qualifies; `js/fun.js` keeps it for the start menu and the tray. Safari
  never fires it, so an iPhone gets the share, add to home screen
  instructions instead. Inside the installed copy (`display-mode:
  standalone`) neither shows. A change to `site.webmanifest` or the icons
  goes through `browser-trophies.mjs`, which asks Chrome itself.
- **`node_modules/` is disposable.** The site has no dependencies and
  neither does the test suite; the only thing that lands there is
  Playwright, installed with `--no-save` for the browser runs.
